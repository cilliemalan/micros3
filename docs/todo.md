# TODO

## Web UI

A browser console for the emulator, to browse and administer buckets and objects. Its design is in [UI.md](UI.md), which this list implements. It runs on its own port in the same process as the S3 API, is compiled into the one static executable, and has a React frontend built with pnpm and Vite, using the Vercel UI SDK (`@ui-sdk/react`, `@ui-sdk/core`, beta). Its backend is a JSON API under `/api/` that calls the store directly.

Decisions, all settled by the owner. UI.md records them, and design.md gets them in U1:

- [x] **UI1. Own port.** Default `3924`, set by `--ui-port <n>` or `MICROS3_UI_PORT`. It must differ from the S3 port. The UI is not served on the S3 port.
- [x] **UI2. No security, own JSON API.** No authentication and no signing in the browser. The API is under `/api/` on the UI port and calls the store directly. The guards in UI6 still apply.
- [x] **UI3. Plain HTTP.** TLS and reverse proxies are the user's concern.
- [x] **UI4. Built with a build step.** The frontend is a Vite and React project, built with pnpm during the CMake build and embedded in the executable.
- [x] **UI5. Always on.** To run without the UI, do not publish its port in Docker.
- [x] **UI6. Request guards.** On every request to the UI port: `Host` must be `localhost` or an IP address (with the UI port if a port is given). `POST`, `PUT` and `DELETE` must carry no `Origin` other than `http://` plus `Host`. Refusals are 403 `AccessForbidden`. This stops DNS rebinding and requests from other web pages. It is not authentication. (Owner's answer to UI.md's Open 1.)
- [x] **UI7. Metadata edited in place.** Stored headers change on the object row, and the blob, ETag and last-modified time stay the same. This differs from S3 on purpose. (Owner's answer to Open 2.)
- [x] **UI8. Node and pnpm are required to build.** As the verifier already requires them. CMake runs pnpm itself. (Owner's answer to Open 3.)
